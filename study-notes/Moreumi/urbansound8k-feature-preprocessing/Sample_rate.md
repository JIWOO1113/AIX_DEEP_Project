# Sample Rate

## 분석 목표

UrbanSound8K 데이터셋의 모든 wav 파일을 머신러닝 모델 입력으로 쓰기 위해 **하나의 sample rate(SR)로 통일**해야 한다. 원본 데이터에 여러 SR이 섞여 있기 때문이다.

이 문서는 **"어떤 SR로 통일하는 것이 최적인가"** 를 객관적 수치로 판단하는 과정과 결론을 정리한다.

---

## 1. 원본 데이터의 Sample Rate 분포 확인

먼저 데이터셋이 어떤 상태인지 점검한다.

### 결과 (8,732개 파일 전수 점검)

| Sample Rate | 파일 수 | 비율 |
|---:|---:|---:|
| 44,100 Hz | 5,370 | 61.50% |
| 48,000 Hz | 2,502 | 28.65% |
| 96,000 Hz | 610 | 6.99% |
| 24,000 Hz | 82 | 0.94% |
| 16,000 Hz | 45 | 0.52% |
| 22,050 Hz | 44 | 0.50% |
| 11,025 Hz | 39 | 0.45% |
| 192,000 Hz | 17 | 0.19% |
| 8,000 Hz | 12 | 0.14% |
| 11,024 Hz | 7 | 0.08% |
| 32,000 Hz | 4 | 0.05% |
| **합계** | **8,732** | **100%** |

### 해석

- 원본 데이터에 **11종류의 sample rate가 혼재**되어 있다.
- 가장 많은 44,100Hz도 전체의 61.5%에 불과하다.
- 8,000Hz~192,000Hz까지 24배 이상 차이가 난다.
- 11,024Hz 같은 비표준 값도 존재한다.

머신러닝 모델은 동일한 형식의 입력을 요구하므로, **하나의 sample rate로 통일이 필수적**이다.

이제 문제는 **"어떤 SR로 통일할 것인가"** 이다.

---

## 2. 어떤 SR로 통일할지 정량 분석

### 2-1. 실험 설계

여러 SR로 변환했을 때의 정보 손실 정도를 측정해서 최적값을 찾는다.

| 항목 | 내용 |
|---|---|
| 비교 SR 후보 | 8000, 11025, 16000, 22050, 32000, 44100, 48000 Hz |
| 기준 SR | 44100Hz (원본 최고 품질, 데이터의 62% 차지) |
| 표본 | 10개 클래스 × 10개 = 100개 파일 |
| 평가 지표 1 | 에너지 보존율 |
| 평가 지표 2 | MFCC 코사인 유사도 |
| 재현성 | random_state=42 |

### 2-2. 평가 지표 설명

SR을 줄이면 두 가지 손실이 발생한다.

**(1) 물리적 정보 손실** — 소리 자체의 주파수 정보가 사라짐  
**(2) 모델 입력 변화** — MFCC 변환 결과의 숫자 값이 달라짐

이 둘은 서로 다른 측면이므로 각각 다른 지표로 측정한다.

#### 지표 1: 에너지 보존율

- **정의**: 원본 wav에 있던 소리 에너지 중, 새 SR로 줄여도 보존되는 비율
- **계산**: FFT로 주파수별 에너지를 구한 후, 새 SR의 Nyquist(SR÷2) 이하 에너지의 비율
- **의미**: "원본 정보가 물리적으로 얼마나 보존되는가"
- **임계값**: 95% 이상

#### 지표 2: MFCC 코사인 유사도

- **정의**: 원본 SR로 만든 MFCC와 새 SR로 만든 MFCC의 코사인 유사도
- **의미**: "모델이 받는 입력이 얼마나 비슷한가" — 머신러닝 모델은 wav가 아니라 MFCC를 입력으로 받기 때문에 이 지표가 분류 성능과 직결됨
- **임계값**: 0.95 이상

#### 두 지표를 함께 쓰는 이유

에너지 보존율은 "원본에 무엇이 있었나"를, MFCC 유사도는 "모델이 무엇을 받나"를 측정한다. 어느 한쪽만 보면 놓치는 경우가 있어 두 지표를 함께 본다.

## 3. 결과 해석

### 3-1. 임계값 통과 SR 식별

평가 지표별로 어떤 SR이 임계값을 통과하는지 정리한다.

#### 에너지 보존율 95% 통과

| SR | 평균 | 통과 여부 |
|---|---:|:---:|
| 8000 | 94.07% | ❌ 미달 |
| 11025 | 95.61% | △ 가까스로 |
| 16000 | 97.90% | ✅ 통과 |
| 22050 | 99.21% | ✅ 통과 |
| 32000 | 99.92% | ✅ 통과 |
| 44100 | 100.00% | ✅ 기준 |

#### MFCC 유사도 0.95 통과

| SR | 평균 | 통과 클래스 수 | 통과 여부 |
|---|---:|:---:|:---:|
| 8000 | 0.880 | 1/10 | ❌ 미달 |
| 11025 | 0.922 | 5/10 | ❌ 미달 |
| 16000 | 0.949 | 5/10 | ❌ 0.001 차이로 미달 |
| 22050 | 0.970 | **8/10** | △ 평균은 통과, drilling/car_horn 미달 |
| **32000** | **0.989** | **10/10** | ✅ **모든 클래스 통과** |
| 44100 | 1.000 | 10/10 | ✅ 기준 |

### 3-2. 수익 체감 분석

SR을 한 단계 올렸을 때 MFCC 유사도가 얼마나 개선되는지 본다.

| 구간 | 평균 개선 폭 | 비고 |
|---|---:|---|
| 8000 → 11025 | +0.043 | 큰 개선 |
| 11025 → 16000 | +0.027 | 큰 개선 |
| 16000 → 22050 | +0.021 | 의미 있는 개선 |
| 22050 → 32000 | +0.019 | 의미 있는 개선 |
| **32000 → 44100** | **+0.011** | **꺾이는 지점** |
| 44100 → 48000 | -0.002 | 사실상 없음 |

**관찰**: 22050에서 32000으로 올릴 때의 개선폭(+0.019)은 16000에서 22050으로 올릴 때(+0.021)와 거의 같다. 즉, 22050Hz가 수익 체감의 시작점이 아니라, **실제로는 32000~44100Hz 사이에서 꺾인다**.

### 3-3. 클래스별 한계 분석

22050Hz에서 임계값에 미달한 클래스:

| 클래스 | 22050Hz MFCC | 32000Hz MFCC | 개선 |
|---|---:|---:|---|
| drilling | 0.925 | 0.974 | +0.049 |
| car_horn | 0.941 | 0.982 | +0.041 |

- **drilling**: 광대역 신호(전 주파수에 에너지 분포). 11kHz 이상에 3.31%의 정보 보유 → 22050Hz로 줄이면 손실
- **car_horn**: 순음 신호(특정 주파수 중심). 리샘플링 시 미세한 주파수 이동이 MFCC에 큰 영향

두 클래스 모두 32000Hz로 올리면 임계값을 안전하게 통과한다.

### 3-4. 데이터 효율 비교

SR에 따른 데이터 크기와 학습 속도:

| SR | 파일 크기 (44100Hz 대비) | 학습 속도 |
|---|---:|---:|
| 8,000 | 18.1% | 5.5배 빠름 |
| 16,000 | 36.3% | 2.8배 빠름 |
| **22,050** | **50.0%** | **2.0배 빠름** |
| **32,000** | **72.6%** | **1.4배 빠름** |
| 44,100 | 100.0% | 기준 |
| 48,000 | 108.8% | 0.9배 (느림) |

## 4. 최종 결정

### 4-1. 선택지 정리

분석 결과를 바탕으로 정당화 가능한 세 가지 선택지가 있다.

| 선택지 | 장점 | 단점 |
|---|---|---|
| **22050Hz** | 학계 표준, 데이터 50% | 평균은 통과하지만 drilling/car_horn 미달 |
| **32000Hz** | 10/10 클래스 통과, drilling 안전 | 비표준값 (학계 직접 비교 어려움), 데이터 73% |
| **44100Hz** | 완벽 보존, 표준 | 데이터 100%, 학습 2배 느림 |

### 4-2. 결정 가이드

분석 결과는 다음 두 선택지를 모두 정당화한다. 팀의 우선순위에 따라 결정 필요.

---

#### 선택지 A: 22050Hz (효율 / 표준 우선)

**선택 근거**:
1. **학계 표준값**
   - UrbanSound8K 공식 벤치마크가 22050Hz
   - 다른 연구와 정확도 직접 비교 가능
2. **학습 효율**
   - 32000Hz 대비 데이터 크기 50% / 학습 속도 2배
3. **평균 임계값 통과**
   - MFCC 유사도 0.970으로 0.95 임계값 통과 (8/10 클래스)

**한계 및 모니터링 사항**:
1. **drilling 클래스의 정보 손실 3.31% 존재**
   - 11kHz 이상의 고주파 정보가 사라짐
   - MFCC 유사도 0.925로 임계값 미달
2. **car_horn 클래스 MFCC 유사도 0.941 (임계값 미달)**
   - 순음 신호 특성상 미세한 주파수 변화에 민감
3. **모델 평가 시 별도 모니터링 필요**
   - drilling, car_horn 클래스의 분류 정확도
   - drilling vs jackhammer 혼동 행렬

**예상 시나리오**: drilling 분류 정확도가 다른 클래스보다 낮게 나올 수 있음.
만약 정확도 차이가 크면 32000Hz로 재검토.

---

#### 선택지 B: 32000Hz (정확성 / 분석 결과 우선)

**선택 근거**:
1. **모든 클래스 임계값 통과**
   - MFCC 유사도 평균 0.989 (10/10 클래스 통과)
   - 22050Hz가 미달한 drilling, car_horn 모두 통과
2. **drilling 클래스 보존 강화**
   - 22050Hz: MFCC 0.925 / 보존율 97.32%
   - 32000Hz: MFCC 0.974 / 보존율 99.71%
3. **수익 체감 직전의 SR**
   - 32000 → 44100 개선은 +0.011로 미미
   - 32000Hz가 가성비 정점
4. **분석 데이터의 직접적 결론**
   - 분석 지표(MFCC, 에너지 보존율) 모두에서 22050Hz보다 우세

**한계 및 비용**:
1. **비표준 SR**
   - UrbanSound8K 공식 벤치마크는 22050Hz 기준
   - 32000Hz 사용 시 다른 연구와 직접 정확도 비교 어려움
2. **데이터 크기 증가**
   - 22050Hz 대비 +45% (전체 약 770MB → 1.1GB)
3. **학습 속도 저하**
   - 22050Hz 대비 약 1.4배 느려짐
---

### 4-3. 팀 논의 시 고려사항

다음 질문에 답하면서 결정한다:

1. **본 프로젝트의 목적은?**
   - 학술 비교 / 논문 작성 → 22050Hz (표준 우선)
   - 실제 응용 / 정확도 최대화 → 32000Hz (분석 우선)

2. **drilling 클래스의 중요도는?**
   - 다른 클래스와 동등 → 22050Hz 무난
   - 특별히 중요 (예: 건설 현장 모니터링) → 32000Hz

3. **학습 환경의 제약은?**
   - GPU 없음 / 시간 부족 → 22050Hz (속도 2배)
   - GPU 충분 / 시간 여유 → 32000Hz (정확도 우선)

### 4-4. 향후 검증 과제

선택과 무관하게 모델 학습 후 다음 항목을 측정한다:

- drilling 클래스의 분류 정확도가 다른 클래스 대비 얼마나 낮은지
- drilling vs jackhammer 혼동 행렬 확인 (두 클래스의 주파수 분포 유사도가 높음)
- car_horn 클래스의 정확도 별도 측정

만약 22050Hz를 선택한 후 drilling/car_horn 정확도가 현저히 낮게 나오면, 32000Hz로 변경 후 재학습하여 비교 검증.
